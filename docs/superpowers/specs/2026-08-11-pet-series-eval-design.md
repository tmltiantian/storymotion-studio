# 宠物短剧自动化 EVAL 与《猫猫事务所：七号纸箱》设计

日期：2026-08-11

## 1. 目标与范围

本轮同时解决两个彼此依赖的问题：

1. 把过去由用户反复指出的坏例固化为可执行的宠物短剧 EVAL，不再依赖成片后逐条口头反馈。
2. 在该 EVAL 门禁下制作原创连续剧《猫猫事务所：七号纸箱》，第一季六集，每集 60-75 秒，首批交付前三集。

EVAL 必须覆盖剧本、跨集连续性、逐镜视觉、动作、口型、声音、剪辑和最终媒体；失败后生成可执行返工单，只重做失败镜头。前三集必须使用原创角色、原创对白和已清权音乐/音效，并从通过 EVAL 的密封目录交付。

## 2. 已确认的历史经验

以下规则来自《冻干到底是谁偷吃的》《猫猫鬼点子》《咪要去面试》和早期漫剧样片的真实坏例：

| 历史坏例 | 根因 | 固化规则 |
| --- | --- | --- |
| 同一角色音色变化、声音生硬 | 音色没有成为生成前契约 | 角色 voice/rate 在剧本冻结前锁定，TTS 资产按哈希绑定 |
| 对白重叠、字幕边界错误 | 用固定镜头时长推测语音，而非实测 WAV | 时间线消费实测 TTS 时长；非设计性重叠为硬失败 |
| 说话时闭嘴、静默时持续张嘴 | 把口型当成镜头级布尔值 | 口型按说话者、可见性和实际声音时间窗审核 |
| 四只前爪、悬空爪、额外身体 | 只描述动作，没有限制总数和连接关系 | 每镜声明可见肢体总数及所属身体；额外或断连肢体为硬失败 |
| 零食袋、纸杯和球体自行移动或复制 | 没有声明唯一性、接触和受力链 | 道具记录数量、位置、支撑点、接触、运动和停止状态 |
| 场景、服装、道具跨镜跳变 | 独立生成只按镜头序号衔接 | 使用 start/end state 与依赖图；相邻切点证据必须通过 |
| 动作卡顿、尾帧冻结、周期性掉帧 | 复制帧、短源补齐或错误光流 | 源镜头先验收动作；禁止 tpad、尾帧复制和默认光流救片 |
| 动作过滑、持续数字推镜 | 用统一慢推代替可读表演 | 每镜只含一个主动作，并具有准备、执行、结果、收势 |
| 交叉叠化出现透明双猫和双道具 | 为追求丝滑无条件叠化 | 默认硬切或动作匹配切；时空跳变只允许短淡黑，不叠加主体 |
| BGM 循环、突兀、压对白或出现杂音 | 多个合成音循环并叠加 | 使用一条获批非循环音乐，分幕剪辑并对白 duck；来源白名单 |
| 自动 OCR 通过但仍有伪字 | 失焦文字和短伪字符漏检 | 自动 OCR、全片接触表和高风险区域放大三层审核 |
| 技术可播却存在剧情或物理错误 | 技术预检被误当成质量验收 | 技术门禁与语义门禁分离，两者均通过才能交付 |
| 旧报告误报当前版本通过 | 素材和审核证据没有绑定 | 视频、剧本、音频、证据和报告全部哈希绑定，变化即 stale |

## 3. 方案选择

采用“统一 EVAL 核心 + 宠物连续剧策略 + 单集状态账本”的结构。

- 不为每个项目复制一套评测器。技术检查、证据生成、审核状态和密封交付复用统一核心。
- 连续剧专属规则放在 `pet_series_policy.json`，避免广告 CTA 规则污染剧情片。
- 每集拥有独立 manifest；跨集共享角色圣经、场景圣经、声音契约和连续性账本。
- 自动检查不能可靠判断解剖、物理因果和剧情吸引力，因此这些项目必须生成规定证据并做显式语义审核，不使用空泛总分代替。

## 4. EVAL 架构

### 4.1 四阶段门禁

1. **剧本预检**：检查时长预算、开头钩子、因果链、每场信息增量、反转、收尾悬念及跨集状态。
2. **逐镜候选 EVAL**：检查角色身份、解剖、表情、动作四阶段、道具物理、口型时间窗和局部连续性。
3. **成片 EVAL**：检查媒体规格、重复帧、冻结、黑帧、音频、字幕、剪辑边界、整体节奏与故事可理解性。
4. **交付门禁**：验证所有报告与素材哈希仍然有效，语义审核全部完成，随后复制到只读语义的密封交付目录。

### 4.2 严重级别

- `P0`：文件不可读、缺音轨、时长错误、素材过期、对白重叠、削波等基础交付失败。
- `P1`：角色漂移、额外肢体、道具复制/自移动、错误说话者、口型明显脱离、意外冻结、无依据场景跳变等内容硬失败。
- `P2`：钩子偏弱、笑点普通、局部节奏拖沓等可优化问题。前三集总体验分低于 85 时仍不得密封。

任何 P0/P1 均不能被总分抵消，也不能用 override 进入正式交付。

### 4.3 评分结构

总分 100，仅在无 P0/P1 时有意义：

| 维度 | 分值 | 核心问题 |
| --- | ---: | --- |
| 剧情与吸引力 | 25 | 3 秒钩子、因果、信息推进、反转、结尾悬念 |
| 角色与视觉 | 20 | 身份、花纹、体型、表情、解剖、场景一致性 |
| 动作与物理 | 15 | 准备/执行/结果/收势，道具唯一性、接触与重力 |
| 对白、口型和声音 | 20 | 音色、说话者、时间窗、重叠、响度、杂音、音乐 |
| 剪辑与观看体验 | 10 | 镜头密度、切点、转场动机、重复帧、眩晕风险 |
| 跨集连续性 | 10 | 线索、角色认知、道具状态、时间线、前后集回收 |

通过条件：总分至少 85，且“剧情与吸引力”至少 20/25，“跨集连续性”至少 8/10。

### 4.4 自动检查

自动检查输出结构化结果和证据，不负责虚构语义结论：

- H.264/AAC、9:16、30 fps、60-75 秒、音频流和 faststart。
- 黑帧、长静音、削波、响度、音频边界跳变和非设计性对白重叠。
- 近似重复相邻帧、长冻结、帧数/时间线偏差和短源补齐。
- 字幕边界、安全区、重复字幕层和内部文案残留。
- 每镜、每条对白、每份证据和每个审核文件的 SHA-256 绑定。
- 连续性账本的引用完整性、前集末状态与本集初状态匹配。

### 4.5 强制语义证据

每个候选至少生成：

- 12 帧动作接触表。
- 说话镜头 8 fps 口型表，并标注实际 audio/mouth onset 与 offset。
- 起点、中点、终点与前后镜切点对照。
- 涉及肢体和道具时的高密度动作表。
- 整集 contact sheet、beat contact sheet 和所有切点 before/after 表。

语义审核必须逐项填写 `PASS`、`FAIL` 或 `UNCERTAIN`，并写具体观察和证据路径。`UNCERTAIN` 与 `FAIL` 同样阻止交付。

### 4.6 自动返工单

每个失败生成一条 repair ticket：

- 集号、镜头号、规则 ID 和严重级别。
- 具体证据和失败时间范围。
- 可观察现象与最可能根因。
- 推荐修改：提示词、构图、动作、音频排程、剪辑或重新生成。
- 允许重做的最小范围和不可变化的已通过依赖。
- 修复后必须重跑的检查集合。

失败镜头移入审计目录；已通过基线不得被覆盖。新的失败模式追加到 bad-case memory，并在后续同类镜头生成前转成预防约束。

## 5. 连续剧设计

### 5.1 系列定位

片名：《猫猫事务所：七号纸箱》

类型：双猫日常微悬疑喜剧。核心观看体验是“前三秒出现异常、两只猫用不同性格调查、结尾反转并留下下一集线索”。

竖屏写实萌宠风，避免复杂拟人手部；以客厅、玄关和厨房三个固定空间为主，降低场景漂移。新场景必须先进入场景圣经再生成。

### 5.2 固定角色

**豆包**：黑白猫、绿色眼睛、白鼻梁和白胸，体型修长。谨慎、聪明、先观察再行动。声音可爱但更冷静，语速适中。

**奶糖**：橘白猫、琥珀眼睛、白口鼻和白胸，体型圆润。冲动、贪吃、常因误操作发现线索。声音更明亮活泼，语速略快。

两只猫的角色参考、描述、voice ID、rate 和音量均作为不可变资产绑定。每集最多新增一个可见配角，前三集不增加第三只猫。

### 5.3 单集节奏

- 0-3 秒：异常画面或悬念句，不使用片头占用钩子。
- 3-15 秒：建立本集问题，并回扣上一集状态。
- 15-45 秒：两轮调查或一次冲突加一次失败尝试。
- 45-60 秒：发现或反转，回答本集表层问题。
- 60-75 秒：角色反应、主线线索和下一集钩子。

每集 9-12 个镜头，平均镜头时长 4-7 秒。一个镜头只承担一个主动作或一个清晰对话节拍，不让模型在镜头内部切场景。

### 5.4 第一季六集大纲

1. **《门口多了一个纸箱》**：玄关出现无寄件信息的纸箱。奶糖以为是零食，豆包发现里面只有一把带“07”图形标记的钥匙。结尾，厨房传来三下敲击声。
2. **《半袋冻干消失了》**：冻干减少，奶糖被怀疑。两猫沿碎屑找到扫地机器人，尘盒中出现与钥匙相同的爪形圆片。结尾，机器人在凌晨自行朝储物柜方向启动。
3. **《凌晨三点的脚步声》**：两猫守夜追踪声音，发现并非陌生动物，而是储物柜后方的机械计时器。计时器停下后，七号钥匙自行从桌面滑到柜门前；下一集要查明外力来源。
4. **《会自己移动的红点》**：红点引导两猫发现柜门下的细线和磁吸装置，解释上一集钥匙移动。线的另一端通向窗台。
5. **《窗台上的陌生爪印》**：窗外配角首次出现，说明它也收到过相同纸箱，并警告七号柜只能在晚上打开。
6. **《七号纸箱打开了》**：七号柜里是主人准备的猫咪寻宝装置和一封无文字图形卡；两猫获得新的“08”标记，开启第二季。

第三集“钥匙移动”在剧本上故意造成疑问，但画面必须明确存在隐蔽细线或画外机械拉力证据，不能真的违反物理规则。第四集负责揭示该因果。

## 6. 首批前三集生产策略

1. 先冻结角色、场景、声音和第一季连续性账本。
2. 三集剧本一起完成，确保前集钩子能在下一集回收；再逐集生成。
3. 每集先生成两镜风险小样：一镜双猫对话、一镜道具物理。两镜通过后才批量生成。
4. 画面使用现有可用网关的 Seedream 角色/场景锚点与 Seedance 动态模型；TTS 使用已验证的豆包 Seed-TTS 2.0 多角色音色。
5. 首轮每镜最多两个候选；出现 P1 时允许第三个定点候选，仍失败则改写构图，不继续抽卡。
6. 先做原生音频驱动口型。只有嘴部失败且身份、眼睛、胡须和头部运动可保留时，才允许局部口型修复；全脸重绘不得晋升。
7. 合成只使用通过逐镜门禁的素材。禁止用频繁正反打、长冻结或多余转场遮住坏口型和坏动作。

## 7. 数据与文件边界

新增能力按职责拆分：

- 连续剧 manifest/schema：描述系列、集、场、镜头、对白、状态与依赖。
- EVAL policy：规则、阈值、严重级别和所需证据。
- 剧本 preflight：纯结构检查，不读取视频。
- 候选 evaluator：逐镜自动指标、证据生成和审核合同。
- episode evaluator：整片技术、剪辑、剧情和连续性审核合同。
- repair planner：把失败结果转成最小返工单。
- continuity ledger：记录每集开头/结尾的角色认知、线索与道具状态。
- delivery adapter：复用现有 Delivery Eval 的 prepare/finalize/deliver 语义。

现有 `factory/pet_sitcom_*`、`factory/pet_longform_review.py`、`factory/pet_replica_review.py` 和外部 `video_delivery_eval.py` 作为复用来源，不直接把广告类 policy 搬入连续剧。

## 8. 错误处理与续跑

- 网关提交、轮询和下载分别持久化状态；网络中断从同一 task ID 续跑，不重复计费。
- 明确 HTTP 拒绝写为 rejected，不伪装成 submitting。
- 每个生成资产原子发布；部分失败不会覆盖上一版完整选择。
- 依赖变化只使真实下游 stale，避免重跑无关镜头。
- 任何外部模型不可用时保留已完成的 EVAL、剧本和资产，不用静态卡片冒充正式集。

## 9. 测试与验收

### 9.1 EVAL 测试

- 用历史坏例建立回归夹具：四爪、悬空爪、道具复制、自移动、错误开口、闭嘴说话、音色漂移、对白重叠、尾帧冻结、重复帧、交叉叠化重影、场景跳变、机械循环 BGM、过期证据。
- 每条规则至少有一个应失败样本和一个相邻应通过样本，防止门禁只会全部拒绝。
- 验证 repair ticket 的镜头定位、证据、最小返工范围和重跑检查准确。

### 9.2 单集验收

- 时长 60-75 秒，9:16、30 fps、H.264/AAC，音频和字幕完整。
- 无 P0/P1，体验总分至少 85。
- 每集开头三秒存在可理解异常；结尾线索在下一集前 15 秒内被承接。
- 豆包、奶糖身份与音色固定；对白重叠为零。
- 可见说话者口型开始/结束与实际声音误差不超过 0.25 秒；静默角色不持续张嘴。
- 无额外肢体、角色复制、道具复制、无外力移动和无依据场景变化。
- 无意外冻结、周期性重复帧、眩晕式切镜或透明叠化重影。
- BGM 来源在白名单内、不机械循环、对白期间自动退让，整片无宽带杂音。

### 9.3 首批交付验收

- 三集分别完成 prepare、语义审核、finalize 和 deliver。
- 三集连续播放时，线索、时间线、场景、角色认知和道具状态无矛盾。
- 每集同时交付 final video、cut plan、source routing、quality report、eval report、semantic review、repair history 和连续性快照。
- 只分享密封目录中的最终视频；候选、失败版本和未封存预览不作为交付物。

## 10. 非目标

- 本轮不制作六集全部成片；先完成六集设计与前三集正式交付。
- 不承诺音素/viseme 级逐字精确口型；验收目标是自然音节级视觉同步。
- 不通过抠图替换参考视频角色，也不复用未清权参考音轨。
- 不用单一模型总分替代逐项证据和硬门禁。
