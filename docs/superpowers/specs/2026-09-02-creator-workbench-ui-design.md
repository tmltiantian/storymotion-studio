# 创作者工作台界面设计

## 目标

将现有制作管理界面升级为面向创作者的 AI 动态漫剧工作台：创作者可以一眼识别项目进度、当前可执行操作、正在生成的任务和可审看的素材，同时不改变既有 API、九阶段流程与审核门禁。

## 使用者与核心场景

创作者进入项目列表后，需要快速完成两件事：新建项目，或继续一个进行中的项目。进入项目后，需要围绕当前阶段完成“看成果、执行生成、审核或返修”，并能随时感知任务进度和费用／风险门禁。

## 体验结构

采用三层创作台，而非额外新路由：

1. 全局导航：品牌、项目、作品、设置；保留九阶段轨道，提示当前所处流程。
2. 项目首页：顶部提供更有创作感的欢迎区和新建项目入口；项目卡展示进度、当前阶段、待处理状态与“继续创作”动作；作业活动被收束为清晰的队列区域。
3. 项目工作区：左侧阶段导航保持不变；中部作为大画布展示剧本、分镜、图片、音频或视频成果；右侧以创作侧栏承载当前阶段状态、生成／审核动作、任务进度和提示信息。

## 视觉方向

- 使用深墨色应用框架、暖白内容画布和电蓝／琥珀色操作强调，形成专业剪辑／生成工作台的层级。
- 采用大尺寸预览区、低密度信息块、柔和阴影与明确卡片边界；不使用竞品品牌、图标或布局复制。
- 交互状态必须保持原有可访问性：按钮名称、加载状态、错误提示、焦点样式和小屏幕适配不可回退。

## 约束

- 不新增网络接口，不修改 Python 制作服务和付费生成逻辑。
- 继续使用 React 19、React Router、Lucide 和现有 CSS；不增加第三方 UI 组件库。
- 沿用现有项目、阶段、视频预检、作业进度和审核组件的数据契约。
- 测试应验证用户可见的创作台结构和关键动作，不能只断言 CSS 类名。

## 验收标准

- 项目列表清晰呈现“新建项目”“继续创作”“项目进度”和“作业活动”。
- 工作区在桌面端形成阶段导航、成果画布、创作侧栏三栏结构；窄屏时可读且不会横向溢出。
- 视频阶段的预检、生成、恢复与审核行为保持原有可用性。
- 现有前端单元测试与构建通过；新增测试覆盖新版创作台标题、项目行动和工作区的侧栏语义。
