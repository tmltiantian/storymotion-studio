# 漫剧工厂简历项目总结设计

## 目标

重构 `/Users/tml/Desktop/j.sorce/漫剧工厂_简历总结.md`，形成一份以真实项目
事实为基础、完整阐述项目交互、bad case 纠正和系统演进的简历母版。

重点不是罗列模型和工具，而是说明项目如何从“能生成视频”迭代为“能发现问题、
定位原因、局部修复、重新验证并保留证据”的生产系统。

## 核心叙事

项目主线采用：

> 用户提出创作目标 -> 搭建首版工作流 -> 用户观看样片并指出 bad case ->
> 复现与拆因 -> 比较解决方案 -> 修改生成/合成/质量门禁 ->
> 重新生成和检查 -> 将经验固化为下一轮规则。

项目不写成一次性成功，也不把失败候选隐藏。失败、判断、取舍和验证共同构成项目
能力证明。

## 内容结构

1. 项目定义与个人职责。
2. 小说到成片的系统流程及模型/工具边界。
3. 用户与系统的完整交互时间线。
4. Bad case 纠正矩阵。
5. 从首版到定版的系统演进。
6. 可核验的最终结果与测试数据。
7. 可直接用于主简历的五条压缩版本。
8. 30 秒、2 分钟和深挖版面试讲述。
9. 常见追问及诚实表述边界。

## 交互时间线

时间线需要覆盖：

- 用户提出“小说转有声漫剧”，并选择 LumenX、AIComicBuilder 和 OpenMontage
  的组合方向。
- 接入统一 AI 网关、Seedream、Seedance 和豆包 Seed-TTS 2.0。
- 用户在每轮样片中指出声音重叠、声线漂移、人物不开口、动作过滑/掉帧、场景
  不一致、转场不符合物理逻辑、配乐生硬等具体问题。
- 系统不只修改成片，而是把问题分别回写到音频先行、微镜头、角色/场景资产、
  生成候选、连续性依赖、合成编码和最终质量门禁。
- 用户选择更合理的 A/B 路线，并要求重新生成更多动作的双人/双猫对话。
- 最终形成双猫 Task 2 的 10 镜、54 秒定版和完整证据链。

时间线使用“反馈、证据、判断、动作、结果”五列，避免写成聊天流水账。

## Bad Case 表达标准

每个 bad case 必须包含：

1. 用户看到的现象。
2. 复现或检测证据。
3. 根因判断。
4. 被否决的简单方案及原因。
5. 最终修改。
6. 可核验效果。
7. 下一轮固化规则。

重点案例：

- 声音重叠与首尾静音误判。
- 多角色声线不统一。
- 生成视频与后置 TTS 解耦导致嘴不动。
- “自然口型”与“逐字音素级认证”的能力边界。
- 长镜头内模型自行切景、角色/场景漂移。
- AI 动作过滑、冻结和编码压平微动作。
- 转场与道具状态不符合物理因果。
- OCR 漏检伪文字及纹理误报。
- 循环 BGM 和剧情节奏不匹配。
- 异步任务中断导致重复提交/重复计费风险。
- 历史审核错误绑定可变候选路径。

## 简历版本

只提供一份五条压缩版，按“产品定义、工作流、bad case 迭代、工程可靠性、
量化结果”组织。内容同时说明产品判断和工程实现，但不针对不同岗位重复包装。

## 事实边界

- 开源项目用于参考或后期，不表述为全部自研。
- 口型表述为自然同步和人工起止误差审核，不宣称逐字音素级认证。
- 不将测试数量等同于业务增长或生产效率。
- 不写未经测量的成本下降、效率提升或用户数量。
- 区分《旧城来信》19 微镜头质量路径与“双猫冻干案”10 镜音频先行路径，
  不混用时长、音轨和测试数据。
- 不在文档中记录任何真实密钥或私有网关凭据。

## 完成标准

- 主简历压缩版可控制在 5 条项目 bullet 内。
- 项目母版完整覆盖用户交互和至少 8 类 bad case。
- 每个量化结果可以从现有日志、审核报告或测试结果中反查。
- 五条简历压缩版与正文事实一致，没有岗位化夸张或重复表述。
- 面试讲述能清楚回答“你做了什么”“为什么这样做”“怎么验证有效”。
