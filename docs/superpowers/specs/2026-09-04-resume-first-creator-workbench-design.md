# 续作优先创作工作台设计

**日期：** 2026-09-04

**状态：** 已确认方向，待实施计划
**目标：** 将现有的制作后台改为适合普通创作者持续完成作品的工作台：默认简单、以“继续上次制作”为入口；熟练用户仍能按需查看镜头、作业、参数和审核证据。

## 背景与问题

当前界面已经能展示项目、九阶段流程和阶段成果，但交互仍偏向内部制作后台：

- 首页以项目列表和阶段进度为主，用户需要自行判断下一步。
- 项目工作区同时展示阶段轨、成果、运行、视频生成和审核，首次使用时不知道从哪里开始。
- 等待确认、需要修改、运行失败等状态虽有技术含义，却没有用创作者语言说明原因、影响和下一步。
- 付费视频的镜头、模型、费用、提交和恢复散落在多个区域，容易让用户在没有充分理解前进入高风险操作。

本次改版不改变后端状态机、审核门禁、付费确认、候选证据或可恢复作业逻辑；只重构前端信息架构和操作路径。

## 设计原则

1. **先续作，后管理。** 只要存在未完成项目，进入工作台先看到最近一次制作停在哪里，以及一个清晰的下一步。
2. **先看成果，再做决定。** 审核阶段先呈现剧本、分镜、图片、音频或视频，随后才呈现通过、修改或运行操作。
3. **默认简单，按需展开。** 只有当前任务、成果和一个主操作默认出现；镜头列表、模型、费用明细、作业 ID 和技术记录放到可展开区域。
4. **所有操作可预期。** 每个行动都明确说明完成后会发生什么；涉及付费、返修影响或作业恢复时给出范围和确认点。
5. **状态使用创作者语言。** 面向用户的文案围绕“已完成什么、现在需要你做什么、之后会怎样”，技术状态仅作为展开信息保留。

## 信息架构

### 首页：续作中心

`/projects` 改为“创作主页”。

- 顶部是 **继续制作** 卡：自动选择最近更新且未完成的项目，显示作品名、当前阶段、已完成阶段数、停止原因和唯一主按钮。
  - 例：`《天庭开盲盒》停在「分镜确认」`、`先看一遍分镜，确认后就会进入资产准备。`
  - 无未完成项目时，改为新建作品引导。
- 其下是 **接下来要做**：最多三项，按优先级列出等待人工确认、需要修改和失败恢复；每一项直接进入对应阶段。
- “全部项目”退到下方，支持搜索、筛选和新建；完成作品可跳转“作品中心”。
- 作业活动仅在存在运行中、失败或可恢复作业时显示，并使用紧凑的状态卡。

### 项目页：当前任务优先

`/projects/:id` 和阶段路由共享同一个项目工作区，布局分为三个层次：

1. **项目上下文条**：作品名、当前阶段、完成进度、返回项目主页。九阶段轨保留，但变为可折叠的“制作地图”；默认突出当前阶段和紧邻的下一阶段。
2. **当前任务区**：页面首屏只包含：
   - 一句状态结论；
   - 对当前成果的预览；
   - 一个主操作（运行、确认、处理修改或恢复）；
   - 一句完成后的下一步预告。
3. **展开式创作控制**：镜头与生成设置、作业活动、审核记录、返修影响、技术详情分别进入独立可展开区，保留现有功能和 API。

对于非当前阶段的直接链接，仍打开指定阶段，但显示“你正在查看 X；项目当前停在 Y”的返回当前任务入口，避免用户误以为阶段顺序被改变。

## 状态与操作模型

前端将已有的后端状态映射为统一的任务卡，不新增或修改后端状态：

| 后端含义 | 面向用户的状态 | 默认主操作 | 操作后预告 |
| --- | --- | --- | --- |
| `not_started` | 准备开始 | 开始制作 | 将生成本阶段成果，随后可预览和确认。 |
| `running` | 正在制作 | 查看进度 | 完成后会自动回到此处供你检查。 |
| `ready` / `waiting` | 等你确认 | 查看成果并确认 | 通过后进入下一阶段。 |
| `changes_requested` | 需要修改 | 查看反馈 | 修改后只重做受影响的内容。 |
| `failed` / `stale` | 制作遇到问题 | 恢复或重新检查 | 不会自动重复提交或重复计费。 |
| `passed` | 已完成 | 查看成果 | 下一阶段已准备好。 |

主操作只在当前任务区出现一次。页面其他区域的同类按钮使用次级样式并跳转到该任务区，避免“多个确认按钮”造成不确定性。

## 视频生成与费用保护

视频阶段保持“预检 → 明确确认 → 提交 → 作业进度/恢复”的现有安全顺序，但调整展示次序：

1. 先看本批镜头的故事目标、选中数量和预计时长。
2. 展开“生成设置”后再编辑镜头列表、提供商和模型信息。
3. 预检成功后出现一张固定的费用确认卡，集中显示：本次镜头数、时长、模型、预计金额、已存在作业的恢复策略，以及提交动作。
4. 作业一旦提交，费用确认卡替换为进度卡；恢复已有任务优先于重新提交，直到后端明确要求新确认。

前端不会绕过 `VideoPreflight`、`confirmVideo`、`testVideo`、`generateVideo` 或后端的付费门禁。

## 组件边界

- `ProjectListPage`：拆为续作卡、待办任务列表、项目库和作业摘要，继续使用 `listProjects` 与 `createProject`。
- `ProjectWorkspacePage`：保留数据加载、路由保护、运行和审核 mutation；增加一个只负责“当前任务”推导与呈现的容器，避免散落的条件分支。
- 新的展示组件：`ResumeProjectCard`、`NextTaskPanel`、`CurrentTaskHeader`、`ProductionMap`、`ExpandablePanel`、`VideoConfirmationCard`。它们只接收现有 API 类型派生的数据，不持有后端业务逻辑。
- `VideoGenerationWorkspace`：保留镜头选择、作业恢复和预检提交逻辑，移动到展开式控制区；费用确认由现有预检结果驱动。
- 样式：在既有 `workbench.css` 中建立“任务卡 / 展开区 / 风险提示 / 紧凑作业状态”四类视觉规则，并在窄屏下让当前任务优先于制作地图。

## 错误、可访问性与响应式

- 加载、空项目、服务不可用和操作失败都提供明确说明与单一重试入口；不会清除用户正在填写的修改反馈。
- 展开区使用原生按钮与 `aria-expanded` / `aria-controls`；主操作在状态变更后保留可见的结果消息。
- 键盘焦点在打开弹窗、展开审核或请求修改后进入相应内容，关闭后回到触发按钮。
- 桌面端可见制作地图与辅助信息；窄屏端默认仅显示当前任务、成果和主操作，地图与高级控制折叠为抽屉式区域。

## 验收标准

1. 有未完成项目时，`/projects` 首屏可在不阅读项目库的情况下明确“继续哪部作品、为什么停下、点击后做什么”。
2. 进入项目后，用户在首屏能看懂当前阶段状态、成果和唯一主操作；审核、运行、返修、视频阶段均适用。
3. 可从任意阶段跳转和回到当前任务，现有阶段路由、审核、影响预览、作业恢复和视频费用确认不回归。
4. 付费视频在用户看到模型、镜头、时长和预计金额之前不能提交；已有任务恢复不触发新提交。
5. 现有单元测试更新后通过，新增覆盖续作卡、当前任务映射、折叠控制和视频确认展示；构建与静态检查通过。

## 非目标

- 不新增用户账户、云端协作、支付系统或新的生成服务。
- 不修改制作阶段、后端审批状态机、模型路由或任何收费策略。
- 不自动批准阶段、自动重提收费作业或隐藏人工审核证据。
