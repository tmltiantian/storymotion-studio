# 漫剧生成质量升级设计

## 1. 背景

当前《旧城来信》使用洋葱网关的 `doubao-seedance-2-0-fast` 生成 6 个约 8 秒的视频镜头，再由 OpenMontage 完成配音、字幕和成片。成片已解决配音重叠和字幕冲突，但仍存在以下视觉质量问题：

- 人物表情指令缺失，前半段多为中性面孔和机械眼神。
- 一个提示词包含多个场景和动作，模型在单个视频内自行切景和转场。
- 通用的 `slow push-in` 和 `slight handheld tension` 运镜产生连续漂移和 AI 插值感。
- 画面提示词不加区分地写入所有主角，与实际镜头参演角色不一致。
- 源视频中已出现双脸、人物变形、生成字幕和构图突变。
- 将 12 fps 动作采样补帧到 30 fps 只改变了帧暴露，没有改变原始运镜的动作语言。

## 2. 目标

建立一条可重复使用的高质量动态漫画工作流，而不是只针对当前样片做手工修补。

成功标准：

- 每个人物镜头都有明确的情绪、眼神、姿态和单一动作。
- 角色身份、服装、脸部特征和参演人数与分镜一致。
- 生成模型不负责跨场景转场，镜头切换由后期时间线控制。
- 动作呈现动态漫画的有意停帧，不出现持续漂移、无意义推镜和过度丝滑。
- 所有源视频经过镜头级质检，不合格镜头单独重生成，不重跑整集。
- 保留现有零音频重叠、实测字幕边界和 OpenMontage 交付链路。

## 3. 非目标

- 不在本轮实现逐音素级口型同步。对话以侧脸、中远景和反应镜头优先，避免假口型成为新的质量问题。
- 不把快速视频模型的整段输出当成不可编辑的成品。
- 不使用源模型生成的字幕、转场或音频。
- 不在未经小样验证前提交整批收费生成任务。

## 4. 选定方案

采用“高质量人物视频 + 环境/物件关键帧 + 动态漫画剪辑”的混合工作流。

- 人物表演镜头：用支持生产角色参考图的高质量视频模型生成。
- 环境、道具和气氛镜头：使用高质量图像模型生成静帧，再在后期加入受控的局部动效或定格。
- 快速模型：`doubao-seedance-2-0-fast` 仅用于草稿和分镜可视化，不用于正式成片。
- 后期：OpenMontage 管理取段、帧暴露、定格、硬切、字幕和配音。

## 5. 数据模型

现有 `Episode.shots` 继续表示故事和音频节拍。新增独立的 `visual_timeline` 表示可以比台词更细的视觉微镜头，解除“一段旁白必须对应一个长视频”的耦合。

每个微镜头包含：

| 字段 | 用途 |
| --- | --- |
| `id` | 稳定且可续跑的镜头标识 |
| `parent_shot_id` | 对应的故事/音频镜头 |
| `scene_context` | 严格对应父镜头来源的单一地点；通用编号标题不是地点。仅当当前父镜头未明示地点时，后续微镜头可使用 `previous-shot-continuity`，且必须经真实的上一微镜头递归解析到具体来源地点 |
| `time_context` | 仅对应父镜头 `scene_title` / `action` 明示的当前场景时间；来源未说明时使用规范值 `source-unspecified` |
| `purpose` | 规范值 `establishing`、`action`、`reaction`、`object`、`turn` 或 `resolve` |
| `character_ids` | 画面中真实出现且在父镜头动作/对白中具名的角色；仅保留说话者反应镜头和恰好两位主角的集合代词例外 |
| `emotion_start` / `emotion_end` | 起始与结束表情 |
| `emotion_intensity` | 1-5 级情绪强度 |
| `gaze` | 视线目标和方向 |
| `pose_start` / `pose_end` | 身体和手部姿态 |
| `action_actor_id` | 动作执行者：画面角色 ID，或保留值 `object` / `environment` |
| `action_code` | 有限动作枚举；提示词由枚举模板生成，不接收自由动作句 |
| `action_target` | 父镜头来源中可验证的单一对象短语；允许时使用规范值 `self` |
| `camera_mode` | `locked`、`micro_pan` 或 `object_insert` |
| `source_duration_seconds` | 请求模型生成的时长 |
| `timeline_duration_seconds` | 成片中的目标时长 |
| `entry_cut` / `exit_cut` | 硬切、动作匹配切或时空黑场 |
| `negative_constraints` | 仅允许规范否定代码：`no_text`、`no_extra_people`、`no_duplicate_anatomy`、`no_scene_change`、`no_camera_motion`、`no_rain`、`no_daylight`、`no_modern_objects`、`no_background_crowd`、`no_lip_closeup`、`no_facial_drift` |

默认每个微镜头在成片中使用 2-4 秒。一条较长旁白可覆盖建立镜头、人物反应镜头和道具特写等多个微镜头。

`action_code` 使用有限的制作枚举：`hold_still`、`gaze_shift`、`blink`、`brow_tighten`、`eyes_widen`、`head_turn`、`reach`、`stop_reaching`、`grasp`、`release`、`hand_over`、`receive`、`insert`、`open`、`close`、`step`、`stop`、`flinch`、`recoil`、`raise`、`lower`、`light_up`、`flicker`、`sway`、`drip`、`ripple`、`reveal`、`listen`、`breathe`。自由动作句和自然语言否定项不是 v3 接口的一部分。

所有自由表演字段只接受简短的构图、表情、视线和姿态描述；换行、多句文本、镜头/转场/时空变化、文字/字幕/水印/标志语义和提示词覆盖语句均拒绝。所有路线拒绝未声明的通用人物和明显新造人名；无角色静帧路线还拒绝身体和手脸描述，角色视频则可使用来源明示的 `手` 等身体表演目标。角色 ID、规范化角色姓名、父镜头 ID 和父镜头序号都必须唯一，否则在任何查找或提示词编译前拒绝。

`previous-shot-continuity` 在时间线验证中递归解析；单独编译提示词时，调用方必须显式传入已解析的具体上一场景，编译器不会仅凭 Episode 父镜头顺序推断。

## 6. 分镜和表演规则

- 每个微镜头只允许一个地点、一个主构图和一个主动作。
- 一个提示词不得同时要求“走进房间、发现道具、人物对话、切到特写”。
- 人物表演必须写成可观察动作，例如“眉心逐渐收紧，眼神从车票移到对方，嘴唇轻微张开”，不只写“害怕”。
- 说话镜头前优先安排一个反应拍，让眼神和姿态先发生变化。
- 对话时避免长时间正面嘴部特写，优先使用侧脸、肩后角度、手部或听者反应。
- 运镜默认为固定机位。只在剧情明确需要时使用小幅横移，不使用持续推拉、自动绕行和镜头内转场。

## 7. 提示词编译

新增结构化提示词编译器，固定按以下顺序输出：

1. 美术风格和画幅。
2. 确切场景和时间。
3. 仅列出当前出现的角色及其参考图关系。
4. 起始构图、起始表情和起始姿态。
5. 镜头内唯一动作。
6. 结束表情、视线和结束姿态。
7. 固定机位或受限的小幅运镜。
8. 负向约束。

每个人物视频提示词都必须包含这组硬约束：

```text
单一连续镜头，固定场景，禁止切景，禁止溶解，禁止推拉变焦，
禁止新增人物，禁止双脸和重复肢体，禁止文字、字幕、水印和标识。
```

## 8. 模型选择和小样淘汰

网关当前可见的候选视频模型包括 `doubao-seedance-2-0`、`doubao-seedance-2-0-fast`、`doubao-seedance-1-5-pro` 和 `wan2.7-t2v`。生产候选仅使用以下两个高质量角色路由：

- `doubao-seedance-2-0`：使用 1080p、生产角色参考图和详细表演提示词。
- `doubao-seedance-1-5-pro`：用完全相同的微镜头和参考图生成对照小样。

`wan2.7-t2v` 不进入人物主线，因为当前工作流没有验证它的生产角色参考图契约。

小样选择两个高风险镜头：

- 单人特写：苏眠从警惕到恐惧的眼神与眉部变化。
- 双人动作：苏眠交出车票，林澈迟疑接过，保持正确手部和视线。

两个模型各生成两个 5 秒、1080p 小样。评分权重：

| 评分项 | 权重 |
| --- | ---: |
| 角色身份和服装一致性 | 25 |
| 表情可读性和情绪变化 | 20 |
| 脸部、手部和肢体结构 | 15 |
| 无自动切景、变形和溶解 | 15 |
| 剧情动作和构图匹配 | 10 |
| 动作节奏和机位稳定 | 10 |
| 无文字、字幕和水印 | 5 |

总分低于 80 或命中任一硬失败项的模型不进入批量生成。硬失败包括角色串脸、多出人物、双脸、严重肢体异常、模型内嵌字幕和镜头内切景。

环境与道具静帧在 `doubao-seedream-4-5` 和 `gpt-image-2` 之间用相同提示词对比。由于当前网关图像生成契约不支持角色参考图，它们不承担人物特写。

## 9. 生成与续跑

- 每个微镜头使用独立输出路径、请求签名、任务 ID 和质检状态。
- 只有提示词、模型、参考图哈希、分辨率或时长变化时才重新提交。
- 已通过的微镜头不因其他镜头失败而重新计费。
- 不合格镜头保留原始文件和原因报告，新版本使用递增的候选编号。
- 每个微镜头在同一模型上最多自动提交 3 个付费候选。三次仍未通过时停止提交，先修改分镜或提示词。
- 小样模型选定前，批量生成命令必须失败关闭。

## 10. 剪辑和动作节奏

- 正式成片保持 1080x1920 和 30 fps 交付契约。
- 普通人物动作默认按 10 fps 暴露，每个不同画面保持 3 个交付帧。
- 情绪特写、道具揭示和悬念停顿可使用 6-8 fps 或明确定格。
- 不对完整 5-8 秒模型视频照单全收，每个候选只选择语义和结构最稳定的 1-3 秒。
- 普通镜头只使用硬切或动作匹配切。禁止通用溶解、人脸变形转场和导入镜头内自带转场。
- 时间或空间跨越可使用 2-4 个交付帧的短黑场。
- 仅允许在静帧环境或道具镜头上使用最大 2% 的受控缩放，人物视频不叠加数字推镜。
- 配音允许跨硬切连续播放，使用 J-cut/L-cut 保持叙事流畅，不为追赶台词而延长差镜头。

## 11. 质量门槛

每个微镜头生成后先写入 `visual_qc.json`，通过后才能进入 OpenMontage 素材包。

自动检查：

- 媒体签名、视频流、时长、分辨率和可解码性。
- 黑帧、空帧、意外场景切换和过高的持续运动。
- 通过 FFmpeg 生成覆盖全时段的接触表。
- 使用已安装的 Tesseract `chi_sim+eng` 扫描中下部字幕区，检出源模型内嵌文字。
- 计算实际不同帧节奏，确保后期的动态漫画暴露策略真正生效。

必须的视觉检查：

- 对照角色参考图检查身份、发型、服装和脸部特征。
- 对照微镜头规格检查表情起止、视线、姿态和单一动作。
- 检查额外人物、双脸、手指、肢体、物件穿插和背景突变。
- 检查模型是否偷偷完成了切景、变焦、绕行或溶解。

硬失败的微镜头不允许使用后期裁切掩盖。只有结构和身份完整、但尾部有少量无关动作时，才允许选取前段。

## 12. 失败处理

- 模型小样全部低于 80 分：停止批量生成，优先修改微镜头复杂度和提示词，不通过反复抽卡掩盖架构问题。
- 单镜头串脸或变形：缩减参演角色和动作，使用新候选编号单独重试。
- 模型仍自行转场：缩短请求时长，将起始与结束姿态改为更接近的动作。
- 内嵌字幕或文字：镜头直接失败，增强无文字约束后重生成。
- 后期节奏仍偏滑：降低该镜头暴露帧率或改用关键帧定格，不全局盲目降帧。

## 13. 验收

工作流验收：

- 长旁白能拆成多个微镜头，台词和视觉时间线不再一对一绑定。
- 不出现实际未参演角色的提示词和参考图。
- 模型小样报告可回溯提示词、模型、输出、评分和选定原因。
- 质检失败时不能生成标记为成功的最终预览。
- 已通过镜头可以在重启后续跑，且不重复计费。

成片验收：

- 1080x1920、30 fps、H.264/AAC，可播放且无黑帧。
- 动态镜头 100% 来自通过质检的微镜头候选。
- 源字幕、水印、双脸、明显肢体错误和模型内转场为 0。
- 每个剧情情绪节拍都有可读的人物表情或姿态反应。
- 镜头默认硬切，无通用溶解和人脸变形转场。
- 动作暴露主要位于 6-10 fps，不存在未经剧情设计的长时间连续推镜。
- 配音时间重叠数为 0，字幕与实测语音边界一致。

## 14. 交付顺序

1. 实现微镜头数据模型和分镜规则。
2. 实现提示词编译器和生产/草稿模型路由。
3. 实现模型小样计划、报告和批量生成门禁。
4. 实现微镜头质检、OCR 和候选状态。
5. 实现微镜头 OpenMontage 时间线和可变动作暴露。
6. 用两个代表镜头完成收费小样比较。
7. 选定模型后分批重生成整集，逐镜通过质检。
8. 重新剪辑、合成、成片预检和视觉审核。
