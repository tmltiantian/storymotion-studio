# 音频优先微分镜生产线设计

## 目标

把“天庭开盲盒”及后续动态漫从“独立长视频拼接后贴配音”改为可验证的音频优先生产线。成片中的每句角色对白必须有可追溯的说话镜头；每个动作只在一个短镜头中完成；没有通过角色、物理、口型和连续性检查的素材不得进入剪辑。

本设计不修改已交付的第 1 集 V1/V2/V3 文件，也不自动恢复视频付费生成。

## 已确认的约束

- 每个微镜头的叙事目的只能是：建立、看见、反应、说一句话、一个动作、结果之一。
- 动作微镜头目标长度为 2–4 秒；若视频服务最短输出为 4 秒，则按 4 秒生成后再精剪。
- 一个镜头最多两名角色；有触碰、递接、按住或力量传递时，只有一个明确接触点。
- 正脸对白镜头必须先有最终角色音频，并将该音频作为参考音频附到视频请求。
- 视频服务是否真的支持中文口型不能靠提示词判断，必须经悟空、杨戬、哪吒各一条短对白的能力测试验证。
- 未通过能力测试的模型不得承接正脸对白镜头；可继续生成无对白动作和环境镜头。
- 角色图、场景关键帧和上一条已通过镜头的末帧是连续性输入，不再是可选建议。

## 新的分层

### 1. 可表演剧本

新增“场景节拍”校验。每个有对白的节拍必须包含：可见触发、说话者的动作或状态变化、台词、至少一个可见反应或结果。纯解释世界观的台词会被拒绝，除非它同时指向画面中可见的对象并改变下一步动作。

每句对白必须绑定唯一说话角色、唯一微镜头和预计时长。对白文本须在 2–4 秒的自然口语范围内；过长的文本必须拆为“说话镜头 + 反应镜头 + 续句”，而不是压入一个长镜头。

### 2. 表演卡与微分镜

在现有 `VisualTimeline` 之前新增可序列化的 `PerformanceCard`。它描述一个微镜头：

- `purpose`：建立、动作、反应、说话、物件或收束；
- `speaker_id` 与 `dialogue_id`：无对白时为空；
- `requires_visible_lipsync`：仅正脸或半身说话镜头为真；
- 起止姿势、视线、主动作人物、动作目标、接触点和道具手；
- `entry_anchor_id`：同场上一条“已通过”镜头的末帧；
- 时间节拍：起势、发力/说话、反应或停稳；
- 负面约束：漂浮、匀速滑行、瞬移、额外人物、错误肢体、文字等。

性能规划器继续负责把父级镜头分成 2–4 秒微镜头，但会输出表演卡所需字段。验证器将在提交前拒绝多主动作、超过两人、无来源的接触动作、或未绑定的可见对白。

### 3. 音频优先和模型能力门

1. 生成最终豆包角色音频；不允许在视频完成后替换对白文本或音色。
2. 将最终音频按 `dialogue_id` 切成单镜头文件，记录哈希、时长、音色和说话者。
3. 对 `requires_visible_lipsync=true` 的表演卡，视频作业必须携带对应音频、角色参考图、场景关键帧和连续性末帧。
4. `GatewayVideoBatch` 必须在状态文件中记录参考音频哈希和模型能力测试标识；缺任意一项即阻止提交。
5. 在任何付费对白批次前，先执行“三角色口型试片”批次。验收通过后写入模型能力档案；不通过时将模型标为 `action_only`，说话镜头保持待处理。

当前网关客户端已支持 `reference_audio`；本次改造把“可传”改为“需要口型时强制传、强制留证”。网关接受音频不等于口型合格，因此能力试片是单独的质量门。

### 4. 角色与场景连续性

每个角色出镜微镜头都必须使用其已审核角色图。每场的第一条人物镜头必须同时使用场景关键帧；后续镜头必须继承同场最近一次通过验收的末帧。系统保存站位、朝向、视线、道具持握手和服装锚点，防止相邻镜头重新抽样。

对于多角色关系，编排器自动将“悟空抬棒、杨戬按住、悟空停住、锁链松动”拆成四条镜头。剪辑只能用通过验收的连续锚点链，不能跨越被淘汰镜头直接假定连续性。

### 5. 动作真实性

表演卡用节拍而非“流畅动作”描述运动。跑步至少分为起跑、三步奔跑、刹停；每条包含脚掌承重、重心方向、加速或减速以及短暂停稳。生成提示固定加入：真实速度、自然加减速、重量转移、清晰接触，禁止匀速补间、漂浮滑行、慢动作和无理由镜头运动。

动作审核对首、中、末三帧检查：角色身份、手脚数量和位置、道具方向、接触点、站位、背景连续性；对白镜头额外检查说话者可见、音频存在、口型是否与语句时长和张口节奏一致。

### 6. 审核状态与剪辑

每条候选片段有以下不可跳过状态：

`planned → audio_ready → submitted → rendered → review_required → approved | rejected | blocked`

- `approved`：唯一允许进入成片时间线的状态；
- `rejected`：保留失败原因、关键帧证据和候选编号，可安全重做；
- `blocked`：缺音频、模型不具口型能力、连续性锚点缺失或预算未授权；
- `submitted`：保留任务标识，恢复轮询而不重复提交。

剪辑器读取审核批准清单和排序，而不是扫描目录中的所有 MP4。若故事需要的镜头被拒绝，成片阶段应报告缺口，不能以不相关镜头填补。

## 代码边界

| 组件 | 改造职责 |
|---|---|
| `factory/performance_planner.py`、`factory/visual_timeline.py` | 输出并验证表演卡、短时长、说话归属、两人上限、接触拆分和动作节拍。 |
| `factory/shot_audio.py`、`factory/local_voiceover.py` | 在视频前生成并切分最终角色音频，建立由 `dialogue_id` 到可验证音频资产的映射。 |
| `factory/micro_video_batch.py`、`factory/gateway_video_batch.py` | 将每条表演卡转为视频作业；对白镜头强制附音频、参考图和连续性帧；写入音频与锚点证据。 |
| `factory/model_bakeoff.py` | 扩展为执行三角色口型试片，并在其报告中记录模型对“说话镜头”和“动作镜头”的许可。 |
| `factory/visual_qc.py`、`factory/pipeline_review.py` | 建立首中末帧与口型审核证据，驱动批准、拒绝和阻塞状态。 |
| 现有本地剪辑流程 | 仅读取批准清单，保持已有成片文件不被覆盖。 |

## 错误处理与成本控制

- 缺最终音频、错说话者、可见对白无口型许可、缺角色图或连续性锚点：本地失败，不提交外部任务。
- 上传音频或提交后发生中断：状态持久化任务标识和音频哈希，仅恢复轮询，不自动重复计费。
- 口型试片、候选镜头和正式批次分开记账；正式批次只接受用户已授权的费用范围。
- 视频模型不支持或未通过口型试片时，系统会明确产出 `blocked`，不会把无口型视频和后贴对白伪装为通过。

## 验收标准

1. 验证器拒绝：长于 4 秒的微镜头、一个镜头三人、未拆接触动作、可见对白无说话者或无音频。
2. 视频作业构建器拒绝：对白镜头未传参考音频、角色图、场景关键帧或连续性末帧。
3. 状态恢复测试证明已提交任务只轮询、不重发；音频变化会使旧视频候选失效。
4. 三角色能力试片分别记录口型评分和结论；未通过的模型无法进入正式对白批次。
5. 审核批准清单外的 MP4 不会被剪辑器读取。
6. 对包含跑步、刹停、递接和按住的示例表演卡，提示中必须出现可验证的节拍、受力和禁止滑行约束。

## 不在本次范围内

- 自动保证任意第三方视频模型的中文口型质量；该项由能力试片决定。
- 重新生成或覆盖已完成的第一季长片段。
- 未经单独授权的外部视频生成、模型充值或付费批次。
