# StoryMotion Studio 制作工作台设计

## 目标

把现有静态作品展示站替换为一个本机优先的完整制作网站，同时覆盖：

- 原创短剧、小说改编和参考复刻三种项目模式；
- 九阶段生产、成果预览、审批、退回和局部返修；
- 收费视频生成前的输入与费用门禁；
- 成片、历史版本、EVAL 和迭代记录的作品中心。

网站采用 React 前端和 Python 本机制作 API。Python 服务直接调用现有统一流水线，不通过 Node 间接拼接命令，也不向浏览器暴露模型密钥。

## 设计原则

1. 九阶段数据模型固定，具体执行路径不固定。
2. 执行状态与审核状态分离，等待确认不等同于执行失败。
3. 用户确认的是有版本和哈希的成果，而不是抽象的阶段名称。
4. 修改前先展示影响范围，局部问题不触发无关内容重做。
5. 收费生成必须显式确认；普通本地计算可由策略自动继续。
6. 网站是制作工具，界面以扫描、比较和重复操作效率为优先。
7. 旧展示站代码在新作品中心验收后删除，真实媒体先迁移再清理。

## 系统结构

```text
React 制作网站
  -> 本机 Python API
      -> 九阶段 Pipeline Runner
      -> H3 / Seedance / Seedream / 豆包 TTS
      -> FFmpeg / OpenMontage
      -> 项目、审核、返修和作品索引
```

前端只接收脱敏后的模型状态、任务进度和受控媒体地址。API 默认只监听 `127.0.0.1`，媒体接口只允许读取已登记的项目产物和迁移后的作品素材。

## 信息架构

### `/projects`

制作工作台首页，包含：

- 进行中、待确认、返修中、失败、已完成项目筛选；
- 项目模式、当前阶段、完成比例、最近更新时间；
- 当前唯一推荐动作，例如“确认分镜”或“查看视频测试”；
- 新建项目入口。

### `/projects/:projectId`

项目生产页使用三栏工作布局：

- 左侧：项目列表和筛选；
- 中间：九阶段导航与当前成果预览；
- 右侧：自动检查、审核意见和操作区。

顶部九阶段导航始终可见。已通过阶段可回看；修改已通过内容前必须先查看下游影响。

### `/projects/:projectId/stages/:stage`

阶段详情由同一页面壳承载，通过阶段预览注册表选择合适的查看器：

- JSON/Markdown：结构化文本和可编辑字段；
- 图片：单图、对照和角色多视图；
- 音频：播放器、波形、角色和台词时间；
- 视频：逐镜候选、完整预览、逐帧和变速播放；
- EVAL：问题类型、时间码、证据图和修复状态。

### `/works`

只展示已经交付的项目，支持按模式、角色和日期筛选。数据来自交付清单，不再硬编码作品数组。

### `/works/:projectId`

展示成片播放器、当前版本、历史版本、角色音色、模型记录、EVAL、关键返修对比和下载入口。

### `/settings`

管理 Provider 可用状态、默认模型、音色映射、输出规格、并发数、费用上限和默认审批模板。密钥只显示“已配置/未配置”，不能从页面读回。

## 固定九阶段数据模型

阶段固定为：

`concept -> script -> storyboard -> assets -> audio -> video -> edit -> eval -> deliver`

固定的是阶段合同、输入输出关系和追踪方式。模式适配器仍可：

- 合并多个阶段的用户确认；
- 将不适用阶段记录为结构化跳过；
- 在一个阶段内部运行多个专业步骤；
- 从失败阶段返回任意合法上游阶段。

## 执行状态与审核状态

### 执行状态

- `pending`
- `ready`
- `running`
- `passed`
- `failed`
- `stale`

### 审核状态

- `not_ready`
- `awaiting_review`
- `approved`
- `changes_requested`
- `auto_approved`
- `skipped`

现有 `blocked` 数据继续兼容读取，但新写入不再用它表示普通的等待审核。真正的外部阻塞单独记录为 `execution_blocker`，例如未配置 Provider 或未开启收费生成。

每次阶段完成都会生成不可变的 `StageRevision`：

- 阶段和修订号；
- 输入签名、执行器及版本；
- 产物路径、类型、哈希和预览方式；
- 自动检查结果；
- 创建时间和生成任务 ID。

`StageReview` 绑定一个明确的 `StageRevision`，保存审批人、结果、意见、证据和时间。修订产物变化后，旧审批不能继续生效。

## 可配置审批策略

每个阶段支持四种策略：

- `manual`：自动检查通过后必须人工确认；
- `automatic`：自动检查通过后自动确认；
- `grouped`：与指定阶段合并为一个确认包；
- `not_applicable`：写入跳过记录，不执行实际生成。

系统提供三个预设：

### 快速试验

确认分镜预演、视频生成前门禁和最终成片，其余阶段自动通过。

### 标准制作

确认剧本、分镜、素材、音频、测试视频、EVAL 和交付。构思与剪辑可在自动检查通过后继续。

### 严格制作

九阶段逐一确认，适合长片、参考复刻和高费用项目。

新建项目时选择预设，项目内可以覆盖单个阶段，但不能关闭视频收费门禁、客观 EVAL 门禁和最终交付确认。

## 阶段审核内容

### 构思

展示故事梗概、受众、平台、风格、目标时长和角色方向。确认后形成故事合同。

### 剧本

展示剧情节拍、逐场对白、角色动机和预计时长。支持修改单句或退回整场，修改后重新计算时长。

### 分镜

逐镜展示缩略图、时长、景别、机位、出场角色、开始/结束状态、道具和前后连接。允许只退回指定镜头。

### 素材

分别审核角色、场景和道具锚点。角色身份、猫咪花色、房间几何和道具数量是强连续性字段。

### 音频

按角色和对白试听，展示波形、字幕时间、语速和情绪。检查音色漂移、机械停顿、杂音和声音重叠。

### 视频

以镜头为单位展示候选、首中尾帧、生成模型、参考素材和口型策略。支持逐帧、慢速、静音、只听对白和候选对比。

### 剪辑

播放完整预览并展示时间线、转场、字幕、音乐和混音信息。问题意见自动携带当前播放时间码。

### EVAL

客观失败不能人工强行通过。主观问题展示证据和置信度，允许确认、返修或标记需要进一步检查。

### 交付

展示母版参数、文件摘要、封面、字幕、质量报告和发布许可提醒，确认后封存为作品版本。

## 视频生成前强门禁

进入收费视频生成前必须满足：

- 剧本、分镜、素材和音频对应修订均已确认；
- 角色、场景和道具连续性自动检查通过；
- 每镜时长、对白区间和口型策略可用；
- Provider、模型、分辨率、预计生成秒数和预计费用已展示；
- 用户明确选择测试生成或批量生成。

第一步默认生成 1 至 3 个高风险镜头。系统优先推荐双人对白、大动作、道具交互、场景转换和口型镜头。只有测试结果通过后才突出显示“批量生成全片”。

## 局部返修关系图

返修请求 `ChangeRequest` 包含：

- 来源阶段和修订；
- 问题类型、严重度和文字说明；
- 可选镜头、角色、场景、道具、对白和时间码；
- 证据文件；
- 建议返回阶段。

提交前先计算并展示 `ImpactPlan`：

- 将失效的阶段和具体镜头；
- 可继续复用的阶段和素材；
- 需要重新调用的收费任务；
- 预计新增时间和费用。

默认依赖示例：

- 修改单句对白：对应音频、含该对白的视频镜头、剪辑、EVAL、交付失效；
- 修改角色外观：该角色素材和包含该角色的视频镜头失效，其他镜头保留；
- 修改一个分镜动作：该镜头视频及其后续剪辑/EVAL/交付失效；
- 只调整字幕样式：视频源镜头保持有效，只重做剪辑/EVAL/交付；
- EVAL 发现三个坏镜头：只创建三个镜头返修任务。

用户确认影响计划后才真正标记内容失效。

## 任务进度与异常恢复

所有长任务由后台任务管理器执行，浏览器刷新或关闭不会中断任务。前端通过事件流接收：

- 当前阶段与镜头；
- 已完成数量和总数量；
- Provider 任务状态；
- 累计预计费用与实际用量；
- 可安全重试的失败原因。

同一项目只允许一个会修改状态的任务运行。网络中断后优先恢复 Provider 任务 ID，不自动重新提交收费请求。任务失败时保留已完成镜头，并提供“重试失败项”而不是整批重跑。

## API 边界

主要接口：

- `GET /api/projects`
- `POST /api/projects`
- `GET /api/projects/{id}`
- `GET /api/projects/{id}/stages/{stage}`
- `POST /api/projects/{id}/stages/{stage}/run`
- `POST /api/projects/{id}/stages/{stage}/approve`
- `POST /api/projects/{id}/stages/{stage}/request-changes`
- `POST /api/projects/{id}/impact-plan`
- `POST /api/projects/{id}/video/test`
- `POST /api/projects/{id}/video/generate`
- `GET /api/jobs/{jobId}`
- `GET /api/jobs/{jobId}/events`
- `GET /api/works`
- `GET /api/works/{id}`
- `GET /api/media/{artifactId}`

媒体接口支持 Range 请求以便拖动视频，但只接受由服务生成的 artifact ID，不接受浏览器传入任意本机路径。

## 作品迁移与旧站清理

1. 扫描旧展示站使用的视频、海报和音频。
2. 为真实作品生成迁移清单，绑定项目、版本、媒体类型和来源。
3. 新作品中心验证播放器、封面、版本和下载。
4. 验证所有旧媒体均被引用或明确归档。
5. 删除旧硬编码页面、旧样式和展示站专用测试。

媒体不会因为删除旧页面而直接删除。无法归属项目的素材进入“历史归档”，由用户后续决定保留或清理。

## 安全与费用

- API 默认仅监听本机回环地址；
- 密钥只从服务端环境读取；
- 状态和报告继续执行密钥脱敏；
- 云端提交使用一次性确认令牌，防止页面重复点击；
- 所有收费操作记录 Provider、模型、镜头、秒数和估算/实际费用；
- 前端不能访问项目根目录以外的文件；
- 删除、覆盖和批量失效操作必须显示影响范围并二次确认。

## 测试与验收

### 后端

- 审核状态与执行状态独立迁移；
- 三种审批预设和阶段覆盖；
- 审批绑定产物哈希；
- 局部返修影响计算；
- 收费任务幂等与恢复；
- 媒体路径隔离和 Range 响应；
- 原有九阶段全量回归继续通过。

### 前端

- 创建三种项目；
- 切换并预览九种阶段产物；
- 通过、退回和查看影响计划；
- 测试镜头和批量生成门禁；
- 刷新后恢复任务进度；
- 作品中心读取真实交付项目；
- 桌面和移动视口无文字、播放器和操作区重叠。

### 端到端验收

使用一个无网络原创项目完整走通创建、自动阶段、人工确认、退回分镜、局部重跑、音频确认、本地视频预览、EVAL 和交付。再用一个模拟 Provider 项目验证测试镜头、费用确认、任务恢复和批量生成门禁，不在自动测试中产生真实云端费用。

## 第一版不包含

- 公网部署和多用户账号；
- 多人同时编辑同一项目；
- 从网页读取或展示完整 API 密钥；
- 在浏览器中实现专业多轨剪辑器；
- 自动发布到抖音或小红书。
